diri vs Superset

Both run many terminal agents in parallel; Superset adds an in-app browser, a hosted MCP and paid remote access, while diri is native, Apache-2.0 and uses plain SSH.

Checked 2026-10-01Sources linked
On this pageAt a glanceWhere diri is differentWhere Superset is a better fitSwitchingSources

Superset is a desktop workspace for running many coding agents in parallel, each in its own git worktree, with a diff viewer, in-app browser, CLI, SDK, hosted MCP server and paid remote access and automations. diri covers much of the same ground as a native app: 21 terminal agents side by side with live status, optional worktrees, a Review panel, and a local MCP server that lets agents start and coordinate other agents. The biggest differences are license, how remote machines are reached, and how far each goes beyond the terminal.

#Where diri is different

#Plain SSH for remote work

diri reaches a server the way you already do, with your OpenSSH config, keys and ProxyJump. It uploads a small helper built for that platform, checks its length, SHA-256 and build ID, and needs no tmux, sudo, Node.js or service on the host. There is no relay in between, and it is free. diri also tests whether a host keeps sessions alive after you disconnect and labels the result. See Remote hosts.

#Coordination without an account

diri's MCP server is a local binary inside the app, connected to Claude Code, Codex and Cursor automatically. Agents can fan work out to helpers in separate worktrees, wait for whichever finishes, review each diff and merge it with integrate. Writes follow the session tree with depth and child caps, and nothing goes through a hosted service. See MCP server and the security model.

#Native, and permissive license

diri is a native app written in Rust with GPUI, licensed Apache-2.0, which allows any use including commercial redistribution. Superset's ELv2 lets you fork and self-host for your team but not offer it as a service.

#Status and accounts

diri reads status through Claude Code hooks, Codex turn notifications, and screen rules for every other agent, and flags destructive-looking permission prompts in red. It can also keep several Claude Code or Codex logins and switch every open tab to another account in one click. See Sessions and Accounts and usage.

#Notes that start work

A diri note is a Markdown plan whose to-dos each start an agent with the note as context, show its progress live, and collect its report. See Notes.

#Where Superset is a better fit

  • More around the terminal. An in-app browser with automatic port detection, setup and teardown scripts per workspace, a built-in chat pane, and a TypeScript SDK. diri has a browser tool for agents, but not a browser pane with port detection.
  • Worktree per task by default. Every Superset workspace is its own worktree, and you can push and open a PR from the diff viewer. In diri worktrees are opt-in and merging a PR opens GitHub.
  • Automations and team features. Pro adds automations, Linear and Slack integrations, and unlimited users, with SSO and audit logs on Enterprise. diri's schedules start an agent with a prompt at a set time on your own Mac while diri is running; diri has no Linear or Slack triggers and no team features.
  • Reach your workspaces from anywhere. The relay lets you open a workspace on another machine without setting up SSH or a VPN. diri's phone companion uses Tailscale instead.

#Switching

Both apps launch the agent CLIs you already have, on your own subscriptions, so the agents and their logins carry over unchanged.

  • Install diri and open your repository: Quickstart.
  • Superset workspaces are git worktrees. Open their folders in diri or let agents make new ones: Worktrees and review.
  • Claude Code and Codex conversations already on your machine appear in Search chats (⇧⌘H), so you can continue them in diri.
  • For a remote box, add it under Settings → Remote with the same ssh destination you use today.
  • Agent pages: Claude Code, Codex, OpenCode, Gemini, Amp.

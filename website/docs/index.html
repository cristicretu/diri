Getting started

Diri documentation

Everything diri does, from the first session to agents that run other agents. New here? The guides walk through the basics with screenshots.

diri runs Claude Code, Codex, Cursor, Gemini and 16 other terminal agents side by side in one native window. It tells you which agents are working, which ones need you, and which are done. Every agent can get its own git worktree, and every change lands in one place to review.

#How diri fits together

diri has three parts. You mostly see the first one.

PartWhat it does
The appThe window: sidebar, terminals, changes, notes, settings. Closing it never stops an agent.
The EngineA background process that owns every session, its status, worktrees and history. The app and the CLI both talk to it.
HoldersOne small process per session that owns the terminal. Agents keep running when the app or the Engine restarts.

Agents you start inside diri can reach the Engine too, through the built-in MCP server. That is how one agent starts helpers, hands them tasks, waits for results and merges their branches.

#Work with many agents

  • Sessions: status, notifications, the sidebar, history, and what survives a restart.
  • Worktrees and review: give each task its own checkout, then review and bring the changes back.
  • Notes: plans and to-do lists you can hand to agents.
  • Recipes and schedules: start an agent at a set time, or save a task and rerun it in one click.
  • Accounts and usage: switch accounts and see what you spend.

#Use these docs from an agent

Every page has a Markdown version: add .md to its path, for example /docs/mcp.md. llms.txt lists them all and llms-full.txt has the whole set in one file. To let an agent search the docs itself, add the docs MCP server:

Terminal
claude mcp add --transport http diri-docs https://diri.sh/mcp
